# 未验证功能清单

> 本项目的单元测试全部使用替身（`requests` / `lxml` / `json5` / `piexif` / `tqdm` / `schedule` 均为 stub），
> **真实微博接口与现场数据只能靠现场单账号验证**。以下功能未经真实环境验证，可能存在 bug；
> 维护或使用时请按「建议验证方式」确认。本清单是静态事实（带 `file:line` 证据），状态变化时同步更新。

## 一、状态定义

| 状态 | 含义 |
| --- | --- |
| **可用，未验证** | 代码接线完整、可开启，但从未在真实服务/真实数据上验证 |
| **未现场跑过** | 逻辑有单测，但未在真实数据盘执行过 |
| **数据事实** | 不是代码缺陷，是已知的数据/平台限制 |

## 二、清单

### A. 可选写入后端（可用，未验证）

这些后端由 `write_mode` 控制，默认关闭；依赖缺失或连接失败只记 warning 并跳过，不阻断其他写入后端。

| # | 功能 | 状态 | 接线与证据 | 建议验证方式 |
| --- | --- | --- | --- | --- |
| A1 | **MySQL 写入后端** | 可用，未验证 | 实现 `util/legacy/backends.py`；`Weibo` 提供 `user_to_mysql/weibo_to_mysql/mysql_*` 薄封装；`write_data` 在 `write_mode` 含 `mysql` 时调用。依赖 `pymysql`（requirements-legacy.txt） | 装 MySQL + pymysql，`write_mode: ["mysql","markdown"]` 单账号跑一轮，核对表结构与更新语义（INSERT … ON DUPLICATE KEY UPDATE） |
| A2 | **MongoDB 写入后端** | 可用，未验证 | 同上；`info_to_mongodb` 为薄封装；`mongo` 与 `mongodb` 两种写法都识别 | 装 MongoDB + pymongo，核对 user/weibo collection 的 find_one/update_one 语义 |
| A3 | **POST 推送后端** | 可用，未验证 | `write_post` 为薄封装，调用 `send_post_request_with_token`（重试 3 次、退避） | 指向测试接口，核对 payload 结构（`{user, weibo:[...]}`）与重试日志 |
| A4 | **Flask REST API** | 可启动，未验证 | 代码在 `scripts/legacy/service.py`（已补项目根 `sys.path` 引导）；需 `pip install -r requirements.txt -r requirements-legacy.txt`；抓取接口会真实启动抓取，SQLite 查询需 `write_mode` 含 sqlite。文档见 `docs/API.md` | `python scripts/legacy/service.py` → 访问 `http://127.0.0.1:5000` 健康/查询接口，再触发一次刷新任务观察日志 |
| A5 | **Docker 部署** | 已配置，未实测构建 | 根目录 `.dockerignore` 排除数据/测试/文档；`deploy/docker-compose.yml` 的 build context 为仓库根、volume 指向 `../config/config.json` 与 `../weibo_data`；`docker compose config` 解析通过 | 启动 Docker 后 `cd deploy && docker compose up -d --build`，确认构建成功、容器常驻并写入 `weibo_data/`；文档见 `docs/部署与验证.md` |

## 四、维护规则

1. **新增功能**若无法在本地真实验证，登记到本清单；
2. 某功能在现场验证通过后，把状态改为「已验证（日期 + 环境）」；
3. 删除归档功能时，同步删除本清单对应行；
4. 本清单只写**静态事实**，不写待办。
