# 部署与验证

面向部署与运维的使用说明：本地/Docker/定时任务怎么部署、升级后怎么验证、出问题怎么排查。
命令均在项目根目录执行；Python 要求 3.10+。

---

## 1. 本地部署

```bash
python3 -m pip install -r requirements.txt   # 核心依赖（抓取/存档/报告）
cp config/config.json.example config/config.json
# 编辑 config/config.json：填 user_id_list、cookie、write_mode 等
python3 weibo.py                 # 抓取
python3 weibo.py --check-config  # 只校验配置，不抓取
```

- 依赖分三个文件：`requirements.txt`（核心，默认只装这个）、`requirements-legacy.txt`（MySQL/MongoDB/Flask 等可选后端，主流程不需要）、`requirements-dev.txt`（ruff/pre-commit/coverage，开发用）。
- **配置相关文件统一放在 `config/` 目录**：`config.json`、`comment_user_filter.txt`、`user_id_list.txt`、`cookie.txt`、`logging.conf`（`config/` 优先，根目录旧位置仅兼容读取）。模板文件：`config/config.json.example`、`config/comment_user_filter.txt.example`、`config/user_id_list.txt.example`、`config/cookie.txt.example`。
- 单元测试不依赖第三方库（测试内自带 stub）：`python3 -m unittest discover -s tests`。
- `output_directory` 支持相对项目根或绝对路径；建议放在独立数据盘，便于备份与迁移。

## 2. Docker 部署（可选）

> **状态：构建链已配置，未实测构建。** 首次构建会真实执行 `pip install`，需要网络。

```bash
# 在 deploy/ 目录下（先把配置准备好，不要把 config.json 打进镜像）
cp ../config/config.json.example ../config/config.json
docker compose up -d --build      # 构建并后台启动（循环间隔由 schedule_interval 控制）
docker compose logs -f            # 观察日志
```

注意：

- 时区：`deploy/Dockerfile` 已安装 tzdata 并固定 `Asia/Shanghai`；
- cookie：优先用环境变量 `WEIBO_COOKIE`（优先级最高）；也可把 `config/cookie.txt` 挂载进容器，并在配置里写 `config/cookie.txt`；
- 数据卷必须挂载 `output_directory`（默认 `weibo_data`），否则容器重建后数据丢失。

## 3. 定时抓取

用 crontab（或 systemd timer）每天/每几天执行一次，配合动态 `since_date`：

```cron
# 每天 03:30 抓取最近 10 天（程序按 since_date=10 计算）
30 3 * * * cd /path/to/weibo-crawler && /usr/bin/python3 weibo.py >> log/cron.log 2>&1
```

- 主爬与评论回填共用数据目录下的 `.weibo_crawler.lock`：同时启动时后启动者会被拒绝（主爬记 warning 返回，回填以退出码 2 退出）；监控定时任务请匹配日志关键字；
- 定时任务不要用 `--check-config` 代替抓取（它不写数据）；
- 跨月/跨年抓取保留 `markdown_split_by=day_by_month`（默认），月份目录自动归档；
- 日志配置在 `config/logging.conf`，日志目录固定为项目根 `log/`，建议加 logrotate。

## 4. 存量评论回填（一次性，可选）

前提：`config.json` 中 `weibo_comment_backfill=1`、（建议）`comment_markdown_backup=1`。

```bash
python3 scripts/weibo_comment_backfill.py --dry-run          # 1) 只读：看将处理多少条
python3 scripts/weibo_comment_backfill.py --max-weibo 20     # 2) 小批试跑
python3 scripts/weibo_comment_backfill.py                    # 3) 全量（后台跑）
```

- 报告与断点在 `weibo_comment_backfill_dir`（默认 `output_directory/report/`）：跨用户总报告在根目录，每用户进度/报告在 `<该目录>/<用户目录名>/`（进度文件 `comment_backfill_progress.json`）；
- 中断（Ctrl-C/崩溃）后重跑即续跑；`--force` 重抓已处理项、`--no-resume` 从头开始；
- 全量前确认磁盘余量：`comment_markdown_backup=1` 时每个 md 一份 `.bak`（与 md 大小同量级）；
- 回填只扫描用户根目录与 `YYYY-MM/` 月份目录；副本目录、`invisible_weibo_dirs` 中的目录不扫描；
- 清理备份：`python3 scripts/weibo_comment_backfill.py --clean-backups --dry-run` 预览。

## 5. 升级检查清单

升级代码后按顺序执行：

1. `python3 weibo.py --check-config` 通过（配置迁移只预览；`--update-config` 才写回，写回前自动备份。若旧配置含嵌套对象导致文本级合并失败，会回退为规范化 JSON，原文件已备份，命令输出会提示）；
2. `python3 -m unittest discover -s tests` 全绿（当前 666 项，以命令输出为准）；
3. 静态检查（可选）：`pip install ruff && ruff check .`（pyflakes 全规则）；
4. 部署自检：`python3 scripts/weibo_selfcheck.py`（动态扫描 `util/`、`scripts/` 检查模块齐全 + 关键模块可导入；`--strict` 时缺配置键也报错；`--compare <目录>` 对比两处文件 md5）；
5. **同步全部代码目录**（只同步 `weibo.py` 会导致版本错配）：`weibo.py`、`__main__.py`、`const.py`、`util/` 全部、`scripts/` 全部、`tests/` 全部、`config/` 下全部模板（`config.json.example`、`comment_user_filter.txt.example`、`user_id_list.txt.example`、`cookie.txt.example`、`logging.conf`）；
6. 备份 `output_directory` 与 `config.json`（或依赖 `markdown_write_backup` / `comment_markdown_backup`）；
7. 单用户/小批跑一轮，按下节检查输出；
8. 存量 md 统一重排（一次性，要求旧格式时用）：
   ```bash
   python3 scripts/weibo_markdown_reorder.py                     # dry-run：只看报告
   python3 scripts/weibo_markdown_reorder.py --users <用户目录名>  # 单用户确认
   python3 scripts/weibo_markdown_reorder.py --fix               # 全量（先备份 .bak.<时间戳>）
   ```
   幂等：第二次运行应全部「无变化」；无 marker 的人工块自动跳过。
9. 编辑快照与状态索引（首次运行自动创建，无需手工）：
   - 每用户目录有 `archive_state_<用户ID>.json`（状态索引）与 `编辑历史/YYYY-MM/`（编辑快照）；
   - 首次运行扫描现有 md 建立索引（只读，几十秒到几分钟）；索引丢失后下次运行自动重建，编辑检测从重建后开始；
   - md 里被编辑过的微博块会多一行 `<!-- edited_at: … -->`（隐藏注释）。
10. 评论刷新：`comment_refresh_scope=all` 每轮刷新本轮抓到的已存档微博（最久未刷新优先，单轮最多 `comment_refresh_limit` 条，默认 300）；评论块按 `cid` 合并，新评论追加、旧评论保留。

## 6. 输出正确性检查（现场验证）

同步到现场后按顺序验证，每步通过再下一步：

**步骤 1：部署自检**

```bash
cd <现场目录>
python3 scripts/weibo_selfcheck.py --compare <工作区目录> --strict
```
预期：`自检通过：模块齐全、关键模块可导入`；`--compare` 应 0 差异。报「模块缺失」→ 补同步；报「导入失败」→ 看堆栈，通常是 `util/` 子包漏同步。

**步骤 2：配置检查（只读）**

```bash
python3 weibo.py --check-config
```
预期：打印配置迁移摘要（预览模式，不写文件）。报「未找到 config.json」→ 配置应在 `config/config.json`。

**步骤 3：单账号小批抓取**

临时把配置改成 1 个账号、`since_date` 近 3 天、关闭评论刷新与全量核对，然后 `python3 weibo.py`。
通过标准：无 traceback；md 有更新（或明确「无新微博」）；没有「写入失败报告」。

**步骤 4：输出检查清单**

| # | 检查 | 通过标准 |
| --- | --- | --- |
| 1 | CSV 行与表头列数一致 | 表头 39 列；含转发的新行也是 39 值（`only_crawl_original=0` 时） |
| 2 | 报告目录正确 | 账号级报告在 `report/<用户目录名>/`；配置了 `*_dir` 的按配置走；无异常缺失 |
| 3 | 媒体文件名与 md 链接一致 | 抽查含多视频/多图的微博：落盘文件名 = md 链接文件名，无断链 |
| 4 | 评论块位置正确 | `#### 评论` 在正文之后、`---` 之前；`<!-- comments: … -->` 与 `<!-- /comments -->` 完整；正文含 `### HH:MM:SS` 样式行时也不插错位置 |
| 5 | 三个运维脚本可运行 | `weibo_comment_backfill.py --dry-run`、`weibo_archive_check_full.py --users <账号> --max-pages 2`、`weibo_markdown_reorder.py` 均正常结束、报告可读、无 OSError 或半截文件 |
| 6 | 文件权限不变 | 评论回填后 md 权限与回填前一致（通常 0644/0640，不应变 0600） |
| 7 | 媒体完整性报告合理 | 开启 `weibo_media_check=1` 时：报告列出的缺失/损坏项可解释；极小 WebM 被标损坏（而不是漏报） |
| 8 | 不可见清单加载正常 | 日志有「已加载已确认不可见的微博 N 条」或明确没有；无「读取失败」「程序性错误」 |

**步骤 5：恢复临时配置**（用备份还原账号数、`since_date`、报告开关）。

**步骤 6：记录结果**

```markdown
## 现场验证记录
- 版本：<git commit 或描述>
- 部署自检：通过 / 失败（说明）
- 配置检查：通过 / 失败（说明）
- 单账号抓取：通过 / 失败（说明）
- 输出检查 1-8：逐项 通过/失败（说明）
- 备注：
```

## 7. 常见问题排查

| 症状 | 先看哪里 | 常见原因 |
| --- | --- | --- |
| 启动即 `ModuleNotFoundError` / `ImportError` | 日志堆栈第一行 | `util/` 或 `scripts/` 漏同步 |
| `AttributeError: 'Weibo' object has no attribute ...` | 日志堆栈 | `weibo.py` 与 `util/` 版本错配（只同步一半） |
| 配置读取失败 | `weibo.py --check-config` 输出 | 路径/格式问题；旧键名可运行期兼容 |
| CSV 列数不对 | 打开 csv 看表头与行 | 历史文件是旧格式；新的含转发行应为 39 值 |
| 报告没生成 | 日志搜「失败」 | 日志会带堆栈，指出具体模块 |
| 评论块异常 | 抽查 md + `comment_retry_<账号>.json` | 评论写回失败会进重试清单 |
| 媒体下载慢/失败多 | 日志 + 媒体报告 | 网络/风控；失败记录见 `not_downloaded.txt` |
| 脚本报 `OSError` | 该脚本报告目录 | 目录权限/磁盘空间；原子写失败会留 `.tmp` 残片（可删） |

## 8. 代码备份与回滚

```bash
# 离线备份（含完整历史，产物约 1–2MB）
mkdir -p <备份目录>
git bundle create <备份目录>/weibo-crawler-$(date +%Y%m%d).bundle --all
git bundle verify <备份目录>/weibo-crawler-$(date +%Y%m%d).bundle

# 恢复
git clone <备份目录>/weibo-crawler-<日期>.bundle weibo-crawler
```

- 备份文件不要上传到公开位置（含历史提交对象），不要放进 `weibo_data/`；
- 回滚：代码 `git checkout <上一版本>` 后重跑；数据用 `comment_markdown_backup=1` 生成的 `*.md.bak.<时间戳>` 覆盖（先停进程）；
- JSON 损坏：程序自动重命名为 `*.corrupt.<时间戳>` 并重建，原始内容可从该文件找回。
